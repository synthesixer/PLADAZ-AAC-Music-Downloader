## 1. รายการข้อจำกัดที่คงสถานะ `TBA` ตามข้อกำหนด (TBA Register)

ตามกฎของโครงการ PLADAZ (Master Prompt ข้อ 4) ค่าที่เป็น `TBA` จะต้องไม่ถูกแต่งเติมหรือกำหนดขึ้นเองโดยพลการ:

1. **~~`TBA-023`~~ — เกณฑ์ประสิทธิภาพ (กำหนดแล้วใน DEC-054):**
   - เกณฑ์: เปิดแอปถึงพร้อมใช้งาน ≤ 5 วินาที และขั้นหลังดาวน์โหลด ≤ 30 วินาทีต่อเพลงยาว 5 นาที; ไม่กำหนดเวลาดาวน์โหลด (ขึ้นกับเครือข่าย) และไม่จำกัดขนาดไฟล์
   - ผลวัด: `scripts/measure_performance.py` กับ build `a4ce579` (2026-10-24): เปิดแอป (`--smoke-test`) ครั้งแรกหลัง build **5.45 วินาที** (เกณฑ์ ≤ 5 วินาที → ไม่ผ่าน), ครั้งถัดมา 3.01 / 3.19 / 2.88 วินาที; ขั้นหลังดาวน์โหลดเพลง 5 นาที: remux 0.28 วินาที, encode 7.81 วินาที (เกณฑ์ ≤ 30 วินาที → ผ่าน, คัดลอกลงโฟลเดอร์ชั่วคราวในเครื่อง ไม่ใช่การ์ดจริง)
   - เวลาเปิดแอปวัดจาก `--smoke-test` (เริ่ม backend + สถานะเริ่มต้น รวมการเรียก `yt-dlp.exe --version` และ `ffmpeg -version`) ไม่รวมการวาดหน้าต่าง WebView2; เวลาเขียนลงการ์ดจริงขึ้นกับความเร็วการ์ด (วัดได้ด้วย `--dest <โฟลเดอร์บนการ์ด>`)
2. **`TBA-026` — อัลกอริทึมเทียบชื่อเพลง/ศิลปิน (Fuzzy Matching Logic) และ MusicBrainz User-Agent:**
   - ปัจจุบันระบบใช้ [`TemporaryExactMetadataMatcher`](file:///e:/Doc/Code/randombullshit/PLADAZV2/src/pladaz/services/metadata_matcher.py) ซึ่งเปรียบเทียบชื่อเพลงและศิลปินแบบตรงตัวหลังแปลงเป็นตัวพิมพ์เล็กและตัดช่องว่าง (Exact Match) เพื่อป้องกันการดึงข้อมูลผิดอัลบั้มตามกฎ `DEC-035`
   - สำหรับการเรียก MusicBrainz API ระบบต้องใช้ค่า `musicbrainz_user_agent` จาก `config.json` หากผู้ใช้ยังไม่ได้ระบุ ระบบจะข้ามการเรียก MusicBrainz และใช้เฉพาะ iTunes Search API หรือข้อมูลจากแหล่งต้นทางแทน โดยไม่แต่งข้อมูลติดต่อผู้พัฒนาขึ้นเอง
3. **`TBA-027` — ค่า Bitrate สำหรับ Fallback Re-encoding (`ffmpeg`):**
   - กรณีคลิปต้นทางไม่มีสตรีม AAC ดั้งเดิม (เช่น มีเฉพาะ Opus/WebM) ระบบจะสั่ง FFmpeg แปลงเป็น AAC-LC (`-c:a aac -profile:a aac_low`) โดยไม่ส่งพารามิเตอร์ `-b:a` (ปล่อยให้ FFmpeg ใช้ค่าเริ่มต้นของตัวเข้ารหัสตามที่กำหนดใน Plan 9.2)

## 2. ข้อจำกัดทางสถาปัตยกรรมและระบบปฏิบัติการ (System & Architectural Limitations)

1. **เพดานความยาวเส้นทางไฟล์ของ Windows (`MAX_PATH` — DEC-043):**
   - บนระบบ Windows ทั่วไปที่ไม่ได้เปิดใช้ระบบ Long Paths เส้นทางเต็มของไฟล์ไม่สามารถยาวเกิน 259 อักขระได้
   - แม้ระบบจะมี Sanitizer ตัดความยาวของแต่ละชื่อโฟลเดอร์/ไฟล์ไม่เกิน 100 อักขระ แต่หากผู้ใช้เลือกโฟลเดอร์ปลายทางที่อยู่ลึกมาก ระบบจะตรวจพบก่อนเริ่มดาวน์โหลดเสียงและปรับงานเป็น `Failed` ด้วยรหัส **`ERR_PATH_TOO_LONG`** ทันที
2. **ไม่มีฟังก์ชัน "Pause" ระหว่างกำลังเขียนข้อมูล (DEC-042):**
   - การควบคุมคิวรองรับเฉพาะ **Start**, **Cancel** (ยกเลิกงานที่กำลังทำ ลบไฟล์ใน Temp และหยุดคิวชั่วคราว) และ **Resume** (เดินคิวต่อสำหรับงานที่รออยู่ในสถานะ `Queued`)
   - ไม่รองรับการหยุดชั่วคราว (Pause) กลางไฟล์ขณะกำลังดาวน์โหลดหรือแปลงเสียง
3. **การเพิ่มเพลงจากเพลย์ลิสต์/อัลบั้มและช่องป้อน URL (DEC-048):**
   - ช่องลิงก์ด้านบนรับได้หลายลิงก์ในครั้งเดียว ลิงก์ละบรรทัด (ลิงก์เพลงเดี่ยว, ลิงก์ Playlist หรือลิงก์ Album — DEC-053)
   - ตามการตัดสินใจ `DEC-048` ระบบตัดหน้าต่างเลือกเฉพาะบางเพลง (Board 12) ออกจากขอบเขต เมื่อวางลิงก์ Playlist ทุกเพลงในรายการจะถูกแตกและเพิ่มเข้าคิวทั้งหมดโดยตรง หากไม่ต้องการเพลงใดสามารถกดปุ่มลบ (`✕`) ที่แถวรายการนั้นในคิวได้
4. **การดาวน์โหลดเพลงแบบเรียงลำดับ (Sequential Worker — DEC-023):**
   - ระบบดาวน์โหลดและประมวลผลทีละ 1 เพลง เพื่อลดโอกาสเกิดปัญหาพื้นที่พักไฟล์เต็มหรือการเขียนไฟล์ชนกันบน Micro SD Card
5. **ข้อจำกัดด้านสัญญาอนุญาตซอฟต์แวร์บุคคลที่สาม (GPLv2+ / GPLv3 Notice สำหรับการแจกจ่ายต่อ):**
   - แพ็กเกจ `dist\PLADAZ\` มีการรวมไลบรารี `mutagen` (GPLv2+) และไบนารี `ffmpeg.exe` (`gyan.dev release_full` build — GPLv3)
   - การใช้งานส่วนบุคคลบนเครื่องของผู้ใช้เองสามารถทำได้ตามปกติ แต่หากมีการแจกจ่ายโฟลเดอร์ไบนารี `dist\PLADAZ\` ให้แก่บุคคลที่สาม ผู้แจกจ่ายต้องปฏิบัติตามเงื่อนไขของสัญญาอนุญาต GPLv2+ และ GPLv3 (เช่น การแนบสำเนาใบอนุญาตและการเปิดเผยซอร์สโค้ดตามที่ระบุไว้ใน [`LICENSE-THIRD-PARTY.txt`](file:///e:/Doc/Code/randombullshit/PLADAZV2/LICENSE-THIRD-PARTY.txt))
6. **โฟลเดอร์ปลายทางไม่จำเป็นต้องอยู่บนไดรฟ์ถอดได้ (DEC-051):**
   - ปุ่ม `CHOOSE FOLDER…` (หน้า Storage และ Settings) รับโฟลเดอร์ใดก็ได้ที่มีอยู่และเขียนได้ รวมถึงไดรฟ์ภายในเครื่อง (เช่น `C:\`) ระบบไม่บังคับว่าต้องเป็น Micro SD Card
   - ปุ่ม `USE THIS CARD` ในหน้า Storage ยังเลือกได้เฉพาะไดรฟ์ถอดได้ที่ Backend สแกนพบ
   - ผู้ใช้ต้องตรวจเองว่าเลือกโฟลเดอร์บนการ์ดก่อนกด Start
7. **ตรวจพื้นที่ว่างก่อนคัดลอก ไม่ใช่ตอนเริ่มเพลง:**
   - ก่อนเริ่มแต่ละเพลง ระบบตรวจว่าการ์ดเชื่อมต่อและเขียนได้ แต่ยังไม่รู้ขนาดไฟล์ จึงตรวจพื้นที่ว่างจริงตอนก่อนคัดลอกจาก Temp ลงการ์ด (ขนาดไฟล์จริง)
   - ถ้าพื้นที่ไม่พอ เพลงนั้นจะดาวน์โหลดและแปลงเสร็จก่อน แล้วจึง `Failed` ด้วย `ERR_SDCARD_INSUFFICIENT_SPACE` และคิวหยุด ไม่มีไฟล์ไม่ครบเหลือบนการ์ด

8. **Browser Authentication (DEC-052):**
   - สถานะ `✓ ACTIVE` หมายถึง `yt-dlp` อ่านคุกกี้จากเบราว์เซอร์ได้เท่านั้น ระบบตรวจไม่ได้ว่าผู้ใช้ลงชื่อเข้าใช้ YouTube อยู่หรือไม่ จะรู้ได้เมื่อดาวน์โหลดเนื้อหาที่ต้องลงชื่อเข้าใช้
   - `yt-dlp` อ่าน cookie store ทั้งหมดของเบราว์เซอร์ (ทุกเว็บไซต์) ทั้งตอนตรวจและทุกครั้งที่ดาวน์โหลดขณะเปิดใช้งาน แอปไม่สามารถจำกัดให้อ่านเฉพาะคุกกี้ของ YouTube ได้
   - Chrome รุ่นใหม่และเบราว์เซอร์ตระกูล Chromium บน Windows อาจป้องกันไม่ให้แอปอื่นอ่านคุกกี้ (App-Bound Encryption) หรือล็อกไฟล์ขณะเปิดอยู่ PLADAZ ไม่พยายามหลบเลี่ยง และแนะนำ Firefox หรือ `cookies.txt` แทน
   - การตรวจจับเบราว์เซอร์ใช้ Windows Registry และการมีอยู่ของไฟล์ cookie store ในตำแหน่งที่ `yt-dlp` ใช้ เบราว์เซอร์แบบ Portable หรือโปรไฟล์ในตำแหน่งอื่นอาจไม่ถูกตรวจพบ
   - `[Unverified]` การอ่านคุกกี้จากเบราว์เซอร์จริงบนเครื่องผู้ใช้ยังไม่ได้ทดสอบ (ทดสอบแล้วเฉพาะ `yt-dlp` 2026.10.21 กับโปรไฟล์ Firefox จำลอง)
