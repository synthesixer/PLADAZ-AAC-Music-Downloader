# PLADAZ — Design Direction & Handoff

Oct 23, 2026 · @Ga

## Part A — Reference Analysis

สรุป: Reference ทั้งสามภาพให้ภาษาภาพแบบ "เครื่องเล่นสื่อ/หน้าต่างโปรแกรมของเล่น" โทนลาเวนเดอร์–ชมพู ที่จัดข้อมูลเป็นกรอบหน้าจอซ้อนกันอย่างมีระเบียบ PLADAZ จะยืมโครงสร้างและบุคลิกนี้ ไม่ยืมตัวละคร โลโก้ หรือข้อความของต้นฉบับ

ชื่อเรียก Reference ในเอกสารนี้:

- **R1** — หน้าแนะนำชุดตัวละคร หน้า 02 (กรอบภาพแบบเครื่องเล่นวิดีโอ ปุ่ม Transport, กล่องคำบรรยาย, กรอบทีวีด้านล่าง)
- **R2** — หน้ารายละเอียด หน้า 03 (กรอบภาพสลับซ้าย–ขวา, แถบหัวข้อทรงยา (pill), กล่องคำพูด)
- **R3** — แผ่นรวม Pixel UI Elements (หน้าต่าง, ปุ่ม OK, Warning dialog, Loading bar, ไอคอนพิกเซล)

R1 และ R2 เป็นสื่อโปรโมตของเกมเชิงพาณิชย์ R3 เป็นงานของนักวาดที่ขายเป็น Element บน Canva ทั้งหมดใช้เป็นแรงบันดาลใจด้านภาษาภาพเท่านั้น

### 1. ภาพรวม Aesthetic

อารมณ์รวมคือ "ร่าเริงแต่มีระบบ" ความน่ารักมาจากสีพาสเทลอิ่มตัวปานกลาง มุมโค้งมาก และสติกเกอร์ประดับ แต่ไม่รกเพราะเนื้อหาทุกชิ้นถูกขังอยู่ในกรอบหน้าจอที่มีขอบหนาชัดเจน สายตาจึงอ่านเป็นบล็อก ๆ ได้ทันที

บุคลิกที่สื่อออกมาคืออุปกรณ์อิเล็กทรอนิกส์ของเล่นยุค Y2K: เครื่องเล่นเพลงพกพา ทีวีจิ๋ว หน้าต่างโปรแกรมยุคแรก ระดับความเป็นทางการต่ำ ความเป็นมิตรสูง และมีความ "หนักแน่นแบบพลาสติก" จากขอบหนา เงาด้านในทึบ และปุ่มที่ดูกดได้จริง

สิ่งที่ทำให้แตกต่างจาก UI Template ทั่วไปคือ Panel ไม่ใช่การ์ดขาวลอยบนเงานุ่ม แต่เป็น "ตัวเครื่อง" ที่มีกรอบนอก (Bezel) และหน้าจอด้านใน (Screen) แยกกันชัด พร้อมรายละเอียดฮาร์ดแวร์ เช่น จุดไฟสถานะ สกรู แถบรูระบายเสียงจุดเล็ก

### 2. Visual Language

**Color Relationships** — ลาเวนเดอร์หลายระดับเป็นโครงสร้าง (พื้นหลัง กรอบ หน้าจอ) ชมพูบานเย็นเป็นตัวเน้นหัวข้อและราคา/ตัวเลขสำคัญ (R1) ฟ้าอ่อนและเขียวมิ้นต์โผล่น้อยมากเป็นประกายเสริม (R1 วงแหวนฟ้าในตรา, R3 ประกายสีเขียว) R3 เพิ่มสีกรมท่าเกือบดำเป็นเส้นขอบ ทำให้มี Contrast จัดในชิ้นเล็ก

**Typography** — R1/R2 ใช้สามระดับ: (1) Wordmark ตัวหนามาก เอียง ขาวมีเงาม่วง (2) หัวข้อในแถบ pill ตัวหนาแคบ ตัวพิมพ์ใหญ่ (3) เนื้อความ Sans-serif น้ำหนักกลาง สีม่วงบนพื้นขาว R3 ใช้ฟอนต์พิกเซลตัวพิมพ์ใหญ่สำหรับป้ายและปุ่ม ไม่ทราบชื่อฟอนต์จริงของต้นฉบับ

**Layout & Composition** — R1 ใช้ Grid สองคอลัมน์ (ภาพใหญ่ซ้าย + ข้อความขวา) ตามด้วยแผงเต็มความกว้าง R2 สลับซ้าย–ขวาเป็นจังหวะซิกแซก แต่ละกรอบมีหัวข้อของตัวเอง ทุกหน้ามีแถบหัวกระดาษที่ขอบล่างเป็นลอนหยัก (Scalloped) และแถบท้ายสีเข้ม

**Spacing & Density** — ความหนาแน่นปานกลาง ช่องว่างระหว่างกรอบประมาณ 2–3% ของความกว้างหน้า (ค่าประมาณ) ภายในกรอบมี Padding กว้าง ข้อความแต่ละกล่องสั้น 2–5 บรรทัด

**Shapes & Geometry** — R1/R2: สี่เหลี่ยมมุมโค้งรัศมีใหญ่ ปุ่มกลม และ pill R3: มุมฉากแบบพิกเซล เส้นขอบหนาเท่ากันทุกด้าน ทั้งสองระบบอยู่ร่วมกันโดย "ตัวเครื่อง" โค้ง ส่วน "หน้าต่างย่อย/สติกเกอร์" เป็นพิกเซล

**Borders, Shadows & Surfaces** — กรอบ R1/R2 ไม่ใช้เส้นดำ แต่ซ้อนลาเวนเดอร์ 2–3 ระดับ + เงาด้านในด้านล่าง ทำให้ดูเป็นพลาสติกนูน R3 ใช้เส้นขอบกรมท่าหนาและเงาแข็งไม่เบลอ

**Iconography** — ไอคอนพิกเซลเส้นหนา (หัวใจ ระฆัง โฟลเดอร์ ลูกศร มือชี้) และปุ่มควบคุมสื่อ (ย้อน หยุดชั่วคราว เล่นรูปหัวใจ หยุด ข้าม)

**Decorative Elements** — ตราวงกลม, ปีกเล็ก, โบว์, ประกาย 4 แฉก, สติกเกอร์ติดเทป, แถบจุด (dot grid), เส้นประใต้หัวข้อ ประดับตามขอบกรอบ ไม่ทับเนื้อหาหลัก

**Contrast & Rhythm** — จังหวะมาจากการสลับกรอบลาเวนเดอร์กับกรอบชมพู และสลับตำแหน่งซ้าย–ขวา จุดชมพูเข้มเล็ก ๆ ดึงสายตาเป็นระยะ

### 4. ข้อจำกัดและสิ่งที่ยังยืนยันไม่ได้

- ไม่ทราบชื่อฟอนต์ ค่า Hex หรือ Token จริงของต้นฉบับ ค่าสีในเอกสารนี้ทั้งหมดเป็น **Proposed Design Token** ที่ประมาณจากภาพแล้วปรับให้ผ่าน Contrast
- ภาพ Reference เป็นภาพนิ่ง ไม่มีหลักฐานเรื่อง Animation, Hover หรือ State อื่น สถานะ Interactive ทั้งหมดเป็นข้อเสนอใหม่
- R1/R2 เป็นหน้าโปรโมตแนวตั้ง ไม่ใช่หน้าจอแอป การจัดวางจึงต้องแปลงเป็นหน้าต่างแนวนอนของ Windows
- R3 มาจากผู้สร้างคนละรายกับ R1/R2 การผสมสองระบบมีกฎกำกับใน Part B (ข้อ "สองภาษา สองหน้าที่") ไม่ได้ผสมแบบสุ่ม

## Part B — Design Direction

แนวคิดหลักชื่อ **Lavender Player OS**: PLADAZ คือ "เครื่องเล่นเพลงของเล่นที่มีระบบปฏิบัติการพิกเซลอยู่ข้างใน" ตัวเครื่องโค้งมนสีลาเวนเดอร์ถือข้อมูลหลัก ส่วนหน้าต่างพิกเซลขอบกรมท่าโผล่มาเมื่อระบบต้องพูดเรื่องจริงจัง เช่น การ์ดถูกถอด หรือผลตรวจไฟล์

### 5. Design Concept

ผู้ใช้เปิดแอปเพื่อทำงานซ้ำ ๆ: วางลิงก์ รอคิว แล้วเสียบการ์ดเข้าเครื่องเล่น (DAP) งานนี้น่าเบื่อและมีความเสี่ยง (ไฟล์เสีย การ์ดหลุด แท็กผิด) แนวคิดนี้ทำให้ส่วนที่น่าเบื่อดูสนุก ขณะที่ส่วนที่เสี่ยงดูชัดเจนและจริงจังกว่า

หลักควบคุมรูปลักษณ์มีข้อเดียว: **ความน่ารักอยู่ที่กรอบ ความชัดเจนอยู่ที่ข้อมูล** การตกแต่งทั้งหมดอยู่บนขอบ หัว และพื้นหลัง ส่วนแถวข้อมูล เส้นทางไฟล์ และสถานะต้องอ่านง่ายเหมือนแอปเครื่องมือทั่วไป

แนวทางนี้ต่างจาก Dashboard มืด ๆ แบบ Downloader ทั่วไป และต่างจาก SaaS ขาวเรียบที่มีการ์ดเงานุ่ม: ไม่มี Sidebar สีเข้ม ไม่มีกราฟ ไม่มีเงาเบลอ

### 6. Design Principles

1. **ตัวเครื่องห่อหน้าจอ (Bezel wraps Screen)**
   - ทุกพื้นที่ทำงานคือกรอบหนาสีลาเวนเดอร์ (หรือชมพู) ที่มีหน้าจอสีขาวอมม่วงอยู่ข้างใน
   - เหตุผล: แยกกลุ่มข้อมูลด้วยวัตถุ ไม่ใช่ด้วยเส้นบาง ๆ อ่านเป็นบล็อกได้ทันที (S1)
   - ใช้จริง: Bezel รัศมี 24px, Padding 14px, หน้าจอรัศมี 16px ขอบ 2px
   - ระวัง: ห้ามซ้อน Bezel ในอีก Bezel; ภายในหน้าจอใช้พื้นอ่อนหรือเส้นประแบ่งเท่านั้น
2. **สองภาษา สองหน้าที่ (Soft hardware vs. Pixel system)**
   - ภาษาโค้งนุ่ม (R1/R2) สำหรับพื้นที่ทำงานประจำ ภาษาพิกเซลขอบกรมท่า (R3) สำหรับ "เสียงของระบบ": ผลตรวจ คำเตือน ข้อตกลง สถานะการ์ด
   - เหตุผล: ผู้ใช้เรียนรู้ได้เองว่ากล่องขอบดำ = เรื่องที่ต้องอ่าน
   - ระวัง: ห้ามใช้ภาษาพิกเซลเป็นของตกแต่งทั่วไป ไม่เช่นนั้นสัญญาณนี้จะหายไป
3. **ชมพูคือการกระทำ (Pink means doing)**
   - ชมพูเข้มใช้กับ: ปุ่มหลักหนึ่งปุ่มต่อหน้าจอ, หัวข้อ pill ของ Section หลัก, งานที่กำลัง Downloading
   - เหตุผล: ใช้สีที่คนจำได้มากที่สุดเป็นตัวบอกว่า "ตอนนี้อะไรกำลังเกิดขึ้น" (S4)
   - ระวัง: ถ้าหนึ่งหน้าจอมีชมพูเข้มเกิน 4–5 จุด ให้ลดลง
4. **สถานะต้องอ่านได้โดยไม่ต้องเห็นสี**
   - ทุกสถานะมีคำ + รูปทรงหรือไอคอน + ระดับความสว่างต่างกัน: Queued (ขอบม่วง พื้นอ่อน), Downloading (ชมพูเข้ม ตัวขาว), Completed (มิ้นต์ ✓), Failed (กรมท่าทึบ ✕)
   - เหตุผล: เป็นข้อกำหนดของระบบ (IR-017) และเป็นสิ่งที่ผู้ใช้กวาดตาดูบ่อยที่สุด
5. **เครื่องเล่นพูดได้ (The player talks)**
   - ข้อความสถานะสด อยู่ในกล่องคำพูดมีหาง ภาษาสั้น ตรง เป็นประโยคเดียว (S6)
   - ระวัง: ห้ามใช้น้ำเสียงตัวละคร/อีโมจิ ต้องบอกข้อเท็จจริง (ขั้นตอน + ตัวเลข)
6. **ของประดับมีงบจำกัด (Decoration budget)**
   - ต่อหน้าจอ: ตรา 1 ชิ้น, ประกาย/หัวใจพิกเซลไม่เกิน 3 จุด, แถบ dot grid ไม่เกิน 1 แถบ ทั้งหมดอยู่นอกแถวข้อมูล

### 8. UX Direction

- **Information Architecture:** 2 ส่วนหลักใน Navigation (Queue, Storage) + หน้ารายละเอียดเพลงที่เข้าจากแถวคิว + Dialog ข้อตกลงครั้งแรก
- **งานหลักต้องจบในหน้าเดียว:** วางลิงก์ → ADD TO QUEUE → START QUEUE โดยเห็นสถานะการ์ดในคอลัมน์ข้างตลอด
- **ความเชื่อใจ:** ผู้ใช้เห็นเสมอว่าไฟล์จะไปอยู่ที่ไหน (Output path, Folder preview) และ Completed หมายถึงผ่าน Validator แล้วเท่านั้น (IR-020)
- **เหตุผิดปกติต้องหยุดสายตา:** การ์ดหลุด/งานล้มเหลวใช้ภาษาพิกเซลขอบกรมท่า ซึ่งเป็น Contrast สูงสุดในระบบ

### 9. Design Decisions และ Trade-offs

- **รายการคิวเป็นแถว ไม่ใช่การ์ดแบบ Grid** (ข้อเสนอใหม่): R2 ใช้กรอบภาพใหญ่ แต่คิวต้องกวาดตาเปรียบเทียบสถานะหลายรายการ แถวจึงอ่านเร็วกว่า เสียความ "นิตยสาร" ไปบ้าง แลกกับความเร็ว
- **ชมพูเข้มขึ้นจากต้นฉบับ** (Adapt): ชมพูของ R1 สว่างเกินสำหรับตัวอักษรขาว
- **ตัดตัวละคร ปีก โบว์ สติกเกอร์ภาพ** (Avoid): เป็นทรัพย์สินทางปัญญาของต้นฉบับ และแอปเครื่องมือไม่ต้องการมาสคอต เหลือเพียงประกาย หัวใจ และตราที่เป็นรูปทรงทั่วไป
- **สองภาษาภาพแทนภาษาเดียว** (New Proposal): เพิ่มความซับซ้อนให้ Designer แต่ได้สัญญาณ "ระบบกำลังพูดเรื่องสำคัญ" ที่ไม่ต้องพึ่งสีแดง
- **UI ภาษาอังกฤษ** (สมมติฐาน): ตามชื่อสถานะในเอกสารโปรเจกต์ และฟอนต์พิกเซลไม่รองรับไทย ถ้าต้องการ UI ไทย ป้ายระบบต้องเปลี่ยนเป็น IBM Plex Sans Thai ตัวหนา

## Part D — Written Design Documentation

### 11. Design Intent

PLADAZ ควรรู้สึกเหมือนหยิบเครื่องเล่นเพลงพกพาสีลาเวนเดอร์ขึ้นมาเปิด แล้วพบว่ามันเป็นระเบียบกว่าที่คิด ผู้ใช้ควรยิ้มเล็กน้อยตอนเปิดแอป และไม่ต้องคิดเลยตอนใช้งาน

ความน่าเชื่อถือไม่ได้มาจากความขรึม แต่มาจากความชัดเจนสามเรื่อง: ไฟล์จะไปอยู่ที่ไหน งานไหนเสร็จจริง และอะไรผิดพลาด ความรู้สึกที่ต้องหลีกเลี่ยงคือ "โปรแกรมโหลดเพลงเถื่อน" (มืด ป้ายโฆษณา ปุ่มเยอะ) และ "แอปสำนักงาน" (เทาขาว เย็นชา)

ความต่างจาก UI ทั่วไปคือทุกพื้นที่เป็นวัตถุที่มีความหนา มีขอบ มีปุ่มที่ดูกดได้ ไม่ใช่แผ่นกระดาษบาง ๆ ลอยบนเงา

### 12. Aesthetic Narrative

ลองนึกถึงหน้าต่างโปรแกรมที่พื้นหลังเป็นลายตารางหมากรุกลาเวนเดอร์จาง ๆ คล้ายผ้าปูโต๊ะ ด้านบนเป็นแถบสีม่วงสด ขอบล่างหยักเป็นลอนเล็ก ๆ เหมือนขอบกระดาษลูกไม้ บนแถบนั้นมีชื่อ PLADAZ ตัวหนาใหญ่ เอียงไปข้างหน้า สีขาว มีเงาม่วงเข้มทึบเยื้องออกมา ให้ความรู้สึกเหมือนสติกเกอร์โลโก้นูน

ใต้แถบหัวคือ "ตัวเครื่อง" สองชิ้นวางคู่กัน ชิ้นใหญ่สีลาเวนเดอร์ถือรายการคิว ชิ้นเล็กสีชมพูถืองานที่กำลังทำอยู่ ตัวเครื่องแต่ละชิ้นมุมโค้งมาก ขอบล่างหนากว่าด้านอื่นเล็กน้อยจากเงาด้านในสีเข้มกว่า เหมือนพลาสติกฉีดขึ้นรูป มีจุดไฟเล็กสองจุด (ดำและเหลือง) ที่มุมซ้ายบน ข้างจุดไฟคือป้ายชื่อทรงยาสีชมพูเข้มเอียงเล็กน้อย

ภายในตัวเครื่องคือ "หน้าจอ" สีขาวอมม่วง มุมโค้งน้อยกว่าตัวเครื่อง ขอบบาง ข้อมูลทั้งหมดอยู่ตรงนี้และดูสงบกว่าภายนอกอย่างชัดเจน: ตัวอักษร Sans-serif สีม่วงเข้มเกือบดำ แถวรายการพื้นม่วงอ่อนมาก แบ่งกลุ่มด้วยเส้นประ

ใต้หน้าจอมีแถวปุ่มกลมแบบเครื่องเล่น ปุ่มกลางยาวกว่าและมีหัวใจพิกเซลสีชมพู ทุกปุ่มมีเงาด้านในด้านล่างจนดูเหมือนกดลงไปได้

เมื่อระบบต้องพูดเรื่องจริงจัง ภาษาภาพจะเปลี่ยน: หน้าต่างมุมฉาก ขอบกรมท่าหนา 3px เงาทึบเยื้องลงขวา แถบหัวเป็นลาเวนเดอร์หรือกรมท่า ตัวอักษรพิกเซลตัวพิมพ์ใหญ่ ความเปลี่ยนแปลงนี้คือสัญญาณให้หยุดอ่าน

จังหวะรวมคือ "ข้างนอกเล่น ข้างในทำงาน": สีสันและรูปทรงทั้งหมดรวมอยู่ที่ขอบ ขณะที่ศูนย์กลางของทุกกรอบเงียบและอ่านง่าย

### 13. Visual Behavior Specification

1. **ลำดับสายตา:** Wordmark → ป้ายชื่อ Section ชมพู → งานที่กำลัง Downloading (ชมพูเข้มในแถว) → ช่องวางลิงก์/ปุ่มหลัก → สถานะที่เหลือ
2. **เด่น vs ถอย:** ชื่อเพลง ชิพสถานะ และเปอร์เซ็นต์เด่น ศิลปิน อัลบั้ม และคำอธิบายถอยด้วย `muted.text` และขนาดเล็กลง 2px
3. **การแยกกลุ่ม:** ระดับ Section ใช้ Bezel; ภายใน Section ใช้พื้น `row` + ช่องว่าง 8px; กลุ่มย่อยใช้เส้นประ ไม่มีระดับที่สี่
4. **ปริมาณสีเน้น:** ชมพูเข้มไม่เกิน 4–5 จุดต่อหน้าจอ ถ้ามีหลายงาน Downloading พร้อมกัน ให้เน้นด้วย Progress bar ไม่เพิ่มพื้นชมพูทั้งแถว
5. **ไม่ให้รก:** ของประดับอยู่บนขอบหรือนอกกรอบเท่านั้น และเป็นไปตามงบในหลักการข้อ 6
6. **ข้อมูลจำนวนมาก:** คิวยาวให้ Scroll ภายในหน้าจอ Bezel และส่วนควบคุมคงที่ ชื่อยาวตัดด้วย … บรรทัดเดียว แถวสูงคงที่ 72px (ค่าเสนอ) เพื่อให้กวาดตาได้
7. **ข้อผิดพลาด:** งาน Failed แสดงเหตุผลหนึ่งบรรทัดใต้ชื่อเป็นสีชมพูเข้มกว่า (#A3245F) เหตุการณ์ที่ต้องตัดสินใจใช้ Dialog พิกเซล

### 15. Consistency Rules

- [ ] ทุก Section หลักเป็น Bezel; ไม่มีการ์ดเงาเบลอที่ใดเลย
- [ ] ภาษาพิกเซลใช้เฉพาะ "เสียงของระบบ" (ผลตรวจ คำเตือน ข้อตกลง สถานะการ์ด แท็บ Nav)
- [ ] ชมพูเข้ม = การกระทำหลักหรืองานที่กำลังทำ ไม่ใช้ตกแต่ง
- [ ] มิ้นต์ = สำเร็จ/ผ่าน เท่านั้น; ฟ้า = วงแหวนตรา เท่านั้น
- [ ] ทุกสถานะมีคำกำกับ และต่างกันที่ความสว่าง ไม่ใช่สีอย่างเดียว
- [ ] ข้อความเล็กสุด 12px และ Contrast ≥4.5:1
- [ ] เส้นทางไฟล์และตัวเลขใช้ IBM Plex Mono ทุกที่
- [ ] ไอคอนเป็นพิกเซลกริดเดียวกัน (ทุกช่องเท่ากัน crispEdges) ไม่ผสมไอคอนเส้นโค้ง
- [ ] ระยะห่างจากสเกล 4 · 8 · 10 · 14 · 18 · 24px เท่านั้น
- [ ] ของประดับไม่เกินงบต่อหน้าจอ และไม่อยู่ในแถวข้อมูล

### 16. What This Design Is — and Is Not

**คือ:** แอปเครื่องมือที่แต่งตัวเป็นเครื่องเล่นเพลงของเล่นยุค Y2K มีโครงชัด ขอบหนา สีลาเวนเดอร์–ชมพู และระบบสองภาษาที่บอกระดับความสำคัญ

**ไม่ใช่:** หน้าโปรโมตเกม (ไม่มีตัวละคร ไม่มีภาพประกอบใหญ่), แอปพิกเซลอาร์ตทั้งแอป (หน้าจอหลักต้องอ่านแบบแอปปกติ), Dashboard มืดแบบนักพัฒนา, หรือ SaaS ขาวเทาที่แค่เปลี่ยนสีปุ่มเป็นชมพู

**รักษาเอกลักษณ์ vs ลอกผิวเผิน:** การรักษาเอกลักษณ์คือการคงความสัมพันธ์ "ตัวเครื่อง–หน้าจอ" และ "นุ่ม–พิกเซล" ไว้ การลอกผิวเผินคือการโปรยหัวใจ ปีก และโบว์ลงบน Layout เดิมของแอปทั่วไป

**สัญญาณว่าเริ่มหลุดทิศทาง:**

- มีเงาเบลอหรือการ์ดขาวลอยปรากฏขึ้น
- ชมพูเข้มถูกใช้กับสิ่งที่ไม่ใช่การกระทำ
- กล่องขอบกรมท่าถูกใช้ห่อเนื้อหาทั่วไปจนไม่มีความหมาย
- ของประดับเริ่มเข้าไปอยู่ในแถวข้อมูล
- มีการเพิ่มสีใหม่ (แดง ส้ม เทา) เพื่อบอกสถานะ

### 18. Mockup Preparation Specification

- **ขนาดอ้างอิง:** หน้าต่าง 1280px กว้าง (Windows desktop) Layout ยืดหยุ่น คอลัมน์ข้างลงล่างเมื่อแคบกว่า \~1000px
- **เทคโนโลยีเป้าหมาย:** HTML/CSS/JS ใน pywebview (Edge WebView2) ตาม IR-015 ทุกค่าใน Part B ทำเป็น CSS Custom Properties ได้ตรง ๆ
- **ฟอนต์:** Dela Gothic One, Silkscreen, IBM Plex Sans Thai, IBM Plex Mono (Google Fonts, OFL) ควร Bundle ไว้ในแอป เพราะ PyInstaller build ต้องใช้งานได้โดยไม่พึ่งเน็ต
- **ไอคอน:** วาดเป็น SVG กริดพิกเซล viewBox 6–9 ช่อง `shape-rendering: crispEdges` ขยายเป็นจำนวนเท่าเท่านั้น (×2, ×3)
- **ลวดลาย:** ตารางหมากรุก, ลอนหยัก, dot grid, ลายปกว่าง ทำด้วย CSS gradient ไม่ต้องใช้ไฟล์ภาพ
- **State ที่ยังต้องออกแบบเพิ่ม:** Hover/Focus/Pressed ของปุ่มทุกชนิด (ข้อเสนอ: Pressed = เงาด้านในหาย + เลื่อนลง 2px), คิวว่าง, ไม่พบการ์ด, พื้นที่ไม่พอ, Validator ไม่ผ่าน
